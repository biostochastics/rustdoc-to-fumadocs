# rustdoc-to-fumadocs codebase audit

This is the historical review of v0.4.0. The fixes, migration instructions, and compatibility results are recorded in the [0.5.0 changelog](CHANGELOG.md) and [current README](README.md). Source locations below refer to the reviewed commit.

Reviewed version 0.4.0 at `ef035bc` on November 17, 2026. The review covered the library, CLI, Cargo discovery, rendering, file output, test helpers, CI, and user-facing usage examples. Two independent GPT-6.2 Astra reviews at xhigh reasoning covered API rendering and generation. The lead review exercised the built CLI, compiled third-party output, and checked the findings against the implementation.

**The first fixes should address pages that fail to build, signatures that change Rust's safety contract, and private members appearing in public documentation.** All 423 repository tests passed. MDX compilation on third-party output nevertheless failed on six pages, including three crate landing pages. Other defects affect successful builds and require assertions about the API shown to readers.

## Verification after the repairs

Version 0.5.0 passed all 488 repository tests on each of Node 20, 22, 24, and 26. V8 measured 92.44% line coverage and 79.68% branch coverage on Node 24, including the CLI. Ten third-party crates produced 1,065 pages across the module, kind, and flat layouts. Every page compiled and all 6,684 internal link checks passed. Real Rust producers covered versions 1.76 through 1.100 and the November 17 nightly. Production builds on Fumadocs 14.7.7, 15.8.5, and 16.19.4 each prerendered 26 generated pages. The v16 check exercised the native MDX adapter. The packed CLI, library, and declarations were also exercised from a clean consumer project. See the [compatibility matrix](README.md#compatibility) and [dependency status](SECURITY.md#dependency-status-for-050).

## High-priority findings

1. **Valid rustdoc prose can break the whole site's MDX build.** The sanitizer preserves HTML void elements such as `<br>` verbatim. MDX expects JSX closing syntax. This accounted for five of the six third-party failures. An email autolink also failed compilation in a focused test. Literal braces pose a different problem. The ordinary sentence `Use {units} as the placeholder` compiled to a JavaScript reference to `units`, which requires a binding at render time. This also means docstrings from third parties can introduce active MDX into a downstream build. Parse source comments as Markdown, emit literal text nodes for prose, and normalize supported HTML into valid MDX. Reserve executable MDX constructs for components generated by the converter. [Docstring conversion](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L435)

2. **A valid item description can break its parent module's index.** The generator takes the first physical line of a docstring and inserts it directly into a Markdown list. In `syn`, an inline-code span containing `HashMap<K, V>` crossed a source newline. The summary cut it after the comma. The item page could represent the original paragraph, but MDX rejected the crate index at that list entry. Derive summaries from the parsed first paragraph and truncate rendered text at a safe boundary. This fix is independent of handling HTML void tags. [First-line extraction](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L133) · [Index bullet](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L1482)

3. **Safety or error documentation can disappear during callout extraction.** The code that removes a section from the body recognizes fences and valid trailing heading markers. A second parser that fills the callout uses different rules. A valid `# Safety ###` lost its safety requirements. A fenced text example containing `# Example` truncated an Errors callout, leaving an open code fence that failed MDX compilation. Use the section and remainder from a single parse for both outputs. [Section removal](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/docs.ts#L310) · [Callout extraction](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/renderer/components.ts#L426)

4. **FFI signatures can advertise unsafe calls as safe.** On formats 57 and 60, a pointer declared `unsafe extern "C-unwind" fn(i32) -> i32` appeared as `fn(i32) -> i32`. The pointer formatter discards its header. The ordinary function formatter also drops the unwind distinction and omits the ellipsis from C variadic declarations. Format the ABI, safety, and variadic parameters from the same underlying representation for declarations and pointers. [Function pointers](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/renderer/types.ts#L120) · [Function ABI](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/renderer/signatures.ts#L43) · [Parameter list](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/renderer/signatures.ts#L77)

5. **Private fields and methods appear on public pages.** With private items present in the input, a public struct's page included a private named field, a private inherent method, and a `pub(crate)` method. The generator filters top-level items, then walks fields and inherent impl children without applying the appropriate visibility rule. The anchor builder indexes these members too. Apply the same member-selection decision to rendering and link registration, preserving trait members whose default visibility follows Rust's trait rules. [Field rendering](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L2112) · [Impl rendering](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L2679) · [Member anchors](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L1309)

6. **A cycle in local glob re-exports can prevent generation from terminating.** The planner drains a queue that grows as glob targets enqueue their child uses. It tracks ancestors when adding a submodule, but revisiting a use at the same destination can append more work without adding a submodule. There is no visited set for those edges. Track expanded uses per destination and distinguish legitimate multiple placements. The missing termination condition was established by inspection. [Queue processing](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L929) · [Glob expansion](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L1087)

7. **The CLI can exit successfully with truncated JSON.** For `syn`, the executable produced a valid 19,571-byte report when redirected to a regular file. A pipe consumer received 512 bytes on this host while the producer exited 0. The CLI writes to stdout and immediately calls `process.exit`. The exact truncation threshold depends on the host and pipe. Set `process.exitCode` and let Node drain stdout. Add a subprocess test that parses the full report from a pipe. Stream injection in the existing test bypasses this behavior. [Stream writes](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/cli.ts#L148) · [Process exit](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/cli.ts#L1039) · [Current JSON test](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/tests/unit/cli.test.ts#L288)

8. **Grouping by kind removes methods and trait implementations.** The grouped renderer calls only the item renderer. The individual-page path separately renders implementations. The same kitchen-sink fixture documents `Widget::new` in module mode and omits its declaration entirely in kind mode. Auto traits and other inherent and trait implementations disappear too. Share an item-body renderer and allocate item-specific anchors on grouped pages. [Grouped output](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L1553) · [Individual output](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L1576)

9. **Workspace mode can omit the primary package or skip a documented library.** Discovery starts from the literal workspace member list, so a nonvirtual workspace's own root package disappears unless listed explicitly. JSON lookup also uses the package name even when the library target has a custom `[lib].name`. A real Cargo workspace produced `umbrella.json` and `custom_lib.json`. Discovery omitted the root package and searched for `alpha.json` for the renamed library. Use Cargo's resolved workspace members and target names, or implement these cases in the TOML reader. Capture skips in the machine-readable report. [Member enumeration](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/workspace.ts#L192) · [JSON lookup](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/cli.ts#L539) · [Filename candidates](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/workspace.ts#L249)

## Performance and verification opportunities

- **Bound workspace memory before optimizing individual string operations.** Workspace generation holds every validated crate, the shared page index, and all generated file contents together. In a sample with 32 copies of a 299 KB rustdoc input, retained heap above baseline after indexing rose from 6.6 MiB for 8 members to 13.1 MiB for 16 and 25.8 MiB for 32. This measures retained heap on one host. A compact route index followed by per-member rendering and writing trades a second read for bounded retention. [Workspace phases](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/cli.ts#L615)
- **Avoid parsing the same docstring for every presentation.** Index summaries call the full link rewriter before taking one line. Doc bodies and callouts repeat the rewrite with different cache keys. Cache the resolved document once per item and derive the summary, heading depth, and callout sections from it. In cfg processing, `requiredFeatures` also walks a chosen `any` branch twice. Benchmark these changes separately from filesystem I/O. [Doc cache](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L1182) · [Index summaries](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/generator.ts#L1482) · [Cfg traversal](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/cfg.ts#L186)
- **Make reported bytes match the files.** The CLI measures JavaScript string length. Across the six-crate run, the output contained 813,495 UTF-16 code units and 815,280 UTF-8 bytes using the same short base URL for both measurements. Use `Buffer.byteLength` for file and total byte counts. [Workspace stats](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/cli.ts#L682) · [Single-crate stats](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/src/cli.ts#L898)
- **Repair the real-crate smoke test.** Its cold-cache path documents a wrapper with `--no-deps` and then looks for the dependency's JSON. The cached path invokes the converter twice with `--json`, counts files in the unwritten directory, and accepts zero. Its post-increment result counters can also stop the script after the first iteration under `set -e`. Select the actual Cargo target, run the writer once, require nonempty output, and compile the resulting pages. [Cold-cache command](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/scripts/test-real-crates.sh#L94) · [Converter invocation](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/scripts/test-real-crates.sh#L130) · [Counters](https://github.com/biostochastics/rustdoc-to-fumadocs/blob/ef035bcbd339468301940c2a05bace6c400af76a/scripts/test-real-crates.sh#L174)
- **Make CI observe the regressions it currently misses.** The workflow uploads `coverage/lcov.info` but Vitest emits text and HTML only. Every Node version also runs the same suite twice. Include the CLI in coverage, emit LCOV in one matrix job, and typecheck the test fixtures. A small Fumadocs build covering literal text and runtime component resolution would exercise behavior beyond the MDX parser. ## Suggested repair order

1. Pin small regression fixtures for the observed MDX compiler failures, safety-section loss, FFI signatures, private members, and truncated CLI output.
2. Fix traversal termination and establish one plan for which pages and members each layout emits. Use it for routes, anchors, sidebar entries, and rendering.
3. Correct Cargo target discovery and regeneration behavior. Make machine-readable reports distinguish complete, partial, and failed output before relying on them in deployment.
4. Profile memory and repeated Markdown processing against the same third-party corpus after correctness fixes land.
